# iTools 运营控制台（itools-console）

面向**运营方**的 Web 后台：看用户、看插件、看数据、处置账号。

**Rust（axum + sqlx）+ 零构建原生前端**，独立进程、独立端口、独立管理员账号体系，
与云同步服务端（`itools-sync-server`）共用同一个 MariaDB 库。

> 命名提醒：这里的「运营控制台」与客户端里那个「管理中心」（`admin.html` + `src/admin/`）
> **不是一回事**。后者是终端用户与插件作者用的 Tauri 窗口；本项目是运营方用的浏览器后台。

---

## 它能做什么 / 不能做什么

诚实分界比功能列表更重要——下面第二列的每一项，界面上都是**禁用状态并写明原因**，
不会给你一个点得动但不生效的按钮。

| 能做（真实生效） | 不能做（需要主服务先支持） |
|---|---|
| 用户列表 / 搜索 / 排序 / 详情 | **禁用账号**：`users` 表没有禁用位，主服务的登录与鉴权也不读它 |
| **强制下线**：删该用户全部会话，主服务下个请求即 401 | **插件下架 / 恢复**：改库不会刷新主服务的市场索引缓存，客户端看不到变化 |
| **删除账号**：账号 + 会话 + 全部同步数据，单事务 | **提审改判**：主服务没有人工改判端点，`manual` 目前是死胡同 |
| 插件市场与提审单只读查询（含模型裁决原文） | **HTTP 请求量 / 带宽 / 耗时 / 插件下载量**：服务端零采集，库里没有这些数据 |
| 注册、会话、同步数据、提审、上线的趋势曲线 | **历史登录次数**：主服务登出即删会话行，登录事件没有留痕 |
| 存储占用排行、命名空间分布 | |
| 控制台账号管理（角色 / 停用 / 重置口令，**真实生效**） | |
| 操作审计（含失败的尝试） | |

「不能做」的那些在概览页与统计页会以「未采集」占位块列出，逐条说明原因与接入条件——
**不画任何估算曲线，包括零线**：一条零线会被读成「这段时间没有流量」，
而事实是「这个东西从来没被记录过」，两者必须看起来完全不同。

## 运行

```bash
cd console
# 配置全走环境变量，见 .env.example
CONSOLE_DB_PASSWORD=... \
CONSOLE_BOOTSTRAP_USER=ops CONSOLE_BOOTSTRAP_PASSWORD=你的初始口令 \
cargo run --release          # 默认 https/http://127.0.0.1:7005

# 静态检查： cargo clippy --all-targets
# 测试：     cargo test        （纯单元测试，不连数据库、不打外网）
```

首次启动时若 `console_admins` 表为空且没配引导变量，进程会**打印指引后退出**——
起一个谁也登不进去的控制台没有意义，而且会让人误以为「服务好了」。
引导出的账号是超级管理员，且**首次登录强制改口令**；表里已有账号后引导变量会被忽略
（不覆盖已有口令，避免留一把后门钥匙）。

配置项全表见 [`.env.example`](.env.example)。几个容易踩的：

| 变量 | 说明 |
|---|---|
| `CONSOLE_TLS_CERT_FILE` / `CONSOLE_TLS_KEY_FILE` | **必须同时配**。只配一个会直接启动失败——后台是带凭据的页面，绝不能静默降级成明文 HTTP |
| `CONSOLE_WEB_DIR` | 前端静态目录。镜像里自带一份兜底；挂载卷覆盖后改前端 scp 即生效，不必重发镜像 |
| `CONSOLE_TRUST_PROXY` | 位于 nginx / frp HTTP 模式之后时必须开，否则登录限流按代理 IP 计数形同虚设 |
| `CONSOLE_TZ_OFFSET_MIN` | 统计分桶的时区偏移（默认 +480）。**不依赖数据库的 `time_zone`**——那个跟着机器走，同一份数据换台机器能画出不同曲线 |
| `CONSOLE_UPSTREAM_HEALTH_URL` | 留空则系统页如实显示「未配置探测地址」，不会谎报主服务故障 |

## 与云同步服务端的关系

```text
  浏览器 ──HTTPS:7005──▶ itools-console ──┐
                                           ├──▶ MariaDB (itools 库)
  iTools 客户端 ─HTTPS:7101─▶ itools-sync ─┘
```

控制台**不代理**主服务的任何流量：主服务挂了控制台照常能用，反之亦然。
两者唯一的耦合点是数据库，外加一次只读的 `/health` 探测。

### 读写边界

| 表 | 归属 | 控制台的权限 |
|---|---|---|
| `users` / `sessions` / `data_records` | 主服务 | **只读**，外加两个运营动作（踢下线、删号，均为纯 DELETE） |
| `plugin_submissions` / `market_entries` | 主服务 | **只读** |
| `console_admins` / `console_sessions` / `console_audit_log` | 本服务 | 读写 |

控制台**不建、不改、不删主服务的任何表结构**，主服务升级时两边不会互相踩。
自己的表一律加 `console_` 前缀防重名——主服务建表是 `CREATE TABLE IF NOT EXISTS`，
一旦重名就是谁先启动谁定表结构、另一方运行时才炸的那种故障。

### 隐私红线

`data_records.v` 是用户真实的同步内容（剪贴板、插件数据）。控制台**只统计条数与字节数**，
源码里没有任何 `SELECT v`，只有 `LENGTH(v)`。这条不是风格问题。

## 安全模型

- **账号隔离**：控制台账号与 iTools 云账号是两套主体，即便同名也不相干。
- **口令**：scrypt（N=16384/r=8/p=1/64 字节），参数与 `server/src/auth.rs` 逐位一致。
- **令牌不明文入库**：`console_sessions` 存的是令牌的 sha256。主服务那边是明文主键、
  一次拖库即拿到全部在线会话；控制台权限更高，这里收紧了。
- **会话有 TTL 且真的会回收**：默认 8 小时，另有定时任务清理过期行。
- **鉴权靠中间件不靠自觉**：受保护路由整组套一层 `middleware::from_fn`，
  新增端点挂进 `protected_routes()` 就自动受保护，想漏都漏不掉。
- **角色**：`super`（可管账号）/ `admin`（可运营）/ `viewer`（只读）。未知角色一律按最小权限。
- **自锁保护**：删除/降级/停用最后一个可用超管会被拒绝。
- **登录限流**：默认每 IP 每 5 分钟 10 次。（主服务的 `/auth/login` 至今零限流，这里不沿用那个状态。）
- **审计**：每个写操作都留痕，**包括失败的尝试**——「谁试图禁用谁但被拒了」和「谁真的删了谁」同样重要。
- **安全响应头**：CSP（`script-src 'self'`、`frame-ancestors 'none'`）、nosniff、`X-Frame-Options: DENY`、
  `Referrer-Policy: no-referrer`、`Cache-Control: no-store`。
- **错误带 code**：前端能区分「没登录 / 权限不够 / 端点不存在 / 服务端 500 / 真连不上」，
  不会把五件事折叠成一句「网络异常」。

## 前端

`web/` 下是**零构建**的原生 ES module + 手写 SVG 图表，没有任何框架与 CDN 依赖
（CSP 只允许 `'self'`，NAS 上也不该依赖外部资源）。改完 scp 上去就生效，秒级。

设计 token 沿用客户端管理中心（`src/admin.css`），主色向官网蓝调靠拢，亮/暗双色。
所有文本一律走 `textContent`——用户名、插件描述、驳回原因都是外部输入，
`h()` 工厂里对 `html` 属性直接抛错，杜绝存储型 XSS。

## 部署（群晖 NAS）

```bash
export NAS_HOST=user@your-nas-host
export NAS_PORT=22
# 首次部署才需要这两个，用于建初始超管
export CONSOLE_BOOTSTRAP_USER=ops
export CONSOLE_BOOTSTRAP_PASSWORD='一个至少 8 位的口令'
./deploy-to-nas.sh v1
```

流程与 `server/deploy-to-nas.sh` 一致：**本地 docker build → save → scp → 远端 load → 换容器**，
NAS 上不做任何编译（群晖那颗 CPU 编 Rust 太慢，2GB 内存编 axum/sqlx 会被 OOM killer 干掉）。

脚本会在服务器上就地生成 `run-console.sh`，其中**数据库口令从正在运行的 `itools-server`
容器的环境变量里读**——口令全程留在服务器上，不经过本机、不进仓库。

> ⚠ 不要改成解析 `run-newN.sh` 文本：那份脚本里的写法是 `-e 'SYNC_DB_PASSWORD=值'`
> （整段被单引号包住），按空白切会把结尾的单引号一起带进来，口令多一个字符、认证必然失败。
> 这个坑踩过一次。

改前端不必重发镜像：`web/` 是挂载进去的，单独 scp 到 `$NAS_CONSOLE_WEB_DIR` 即可。

### 外网暴露

生产是 frp 纯 TCP 透传（腾讯云 frps → 群晖 frpc），控制台自己终结 TLS，
证书与云同步服务端共用同一份。7005 端口需要一条 frp 隧道。

当前 NAS 上跑的是一个**独立的 frpc 实例**（容器 `itools-frpc`），只带 7005 这一条隧道，
配置在 `/volume1/docker/itools-build/frpc-console.toml`。这样做是因为主 `frpc.toml` 属 root、
本账号无法写入，而重启 frpc 套件会连 SSH 隧道一起断——万一配置有误就再也连不上机器了。

> 更干净的长期做法：把 7005 那条 `[[proxies]]` 并进主 `frpc.toml`，然后停掉 `itools-frpc` 容器。
> 这需要 root 权限，留给运维在方便时做。

## 已知限制

1. **用户列表的聚合是现算的**：子查询会全表扫 `data_records`。当前规模（几十个账号）毫无压力；
   涨到十万级时要改成物化统计表，且应当由主服务在写入时维护，而不是控制台每次现算。
2. **frp TCP 透传下拿不到真实客户端 IP**：服务端看到的对端恒为回环地址，
   `CONSOLE_TRUST_PROXY` 也无 XFF 可用。这意味着登录限流实际是全局闸门，
   审计日志里的 IP 也只是回环地址。若要真实 IP，需要 frp 改 HTTP 模式或前置反代注入 XFF。
3. **首次建表在群晖上较慢**（实测 1.5–3.4 秒/张，会触发 sqlx 的 slow statement 警告）。
   只发生在第一次启动，之后 `IF NOT EXISTS` 是 no-op。

## 下一步（第二阶段）

给云同步服务端打两个补丁，把上面表格右列的两项打通：

1. **`users.status` 禁用位**：加列 + `login` 拦截 + `authenticate` 复查 + 禁用时清会话。
   四处缺一不可——只删会话不拦登录，用户下一秒就能登回来，那是典型的假功能。
   客户端侧还要能把 403 与原因如实显示出来，而不是笼统显示成「未登录」。
2. **请求指标采集**：中间件统计 method / 路由 / 状态码 / 耗时 / 字节数，
   内存聚合后按小时 UPSERT 落库，控制台的「未采集」占位块随之换成真实曲线。
