## 一、任务与本次交付范围

海风哥的原话是「做一个后台管理系统，管理用户，禁用账号，插件管理，流量状况等等，部署到 nas 的服务器上」。

拍板的四个决策：
1. **独立管理员表 + 独立口令**（不复用 `SYNC_ADMIN_USERS` 白名单）
2. **独立静态站 + 独立端口**（7005）
3. **流量统计聚合落库**
4. 我做完整实现与部署脚本

开工后勘察出一个必须先讲清的事实，据此把范围切成两步：

**「禁用账号」与「流量统计」这两项，无论如何都要改云同步服务端的源码。**
- 禁用：`users` 表没有禁用位，且主服务的 `login`（`server/src/routes.rs:398`）只校验口令、
  `authenticate` 只查 `sessions`——控制台单方面加一列改一改是**彻底无效**的。
- 流量：主服务零指标采集，库里根本没有请求量/带宽/耗时数据，查不到不存在的东西。

海风哥当时明确「其它会话正在改服务端源码」，因此选择**分两步**：
第一阶段交付**零服务端改动**的部分（本文档），第二阶段再打服务端补丁。

## 二、架构与关键文件

```text
  浏览器 ──HTTPS:7005──▶ itools-console ──┐
                                           ├──▶ MariaDB (itools 库)
  iTools 客户端 ─HTTPS:7101─▶ itools-sync ─┘
```

控制台**不代理**主服务流量，两者互不依赖（除数据库与一次只读的 `/health` 探测）。

### 后端（`console/src/`）

| 文件 | 职责 |
|---|---|
| `main.rs` | 启动、引导首个管理员、TLS 终止（手写 accept 循环，与主服务同一套）、过期会话回收 |
| `config.rs` | 全部配置（`CONSOLE_*` 前缀，与主服务 `SYNC_*` 隔离）。TLS 只配一个会**直接报错退出** |
| `auth.rs` | scrypt 口令（参数与 `server/src/auth.rs` 逐位一致，测试里钉了同一条 Node 向量）+ 令牌 sha256 |
| `ratelimit.rs` | 登录限流（固定窗口，纯内存） |
| `store/mod.rs` | 连接池、`console_*` 三张表 DDL、**主服务库能力探测**（`Caps`） |
| `store/admins.rs` | 控制台账号与会话（令牌存哈希、有 TTL、联表查角色故改角色立即生效） |
| `store/audit.rs` | 审计写入与查询 |
| `store/users.rs` | 终端用户查询 + 踢下线 + 删号。**没有任何 `SELECT v`，只有 `LENGTH(v)`** |
| `store/plugins.rs` | 市场与提审单查询，全只读 |
| `store/stats.rs` | 统计聚合。分桶**不依赖数据库时区**，在 SQL 里手算桶号 |
| `routes/mod.rs` | 路由组装、**统一鉴权守卫**、错误格式（带 `code`）、客户端 IP 中间件、安全响应头 |
| `routes/*.rs` | 各功能端点 |

### 前端（`console/web/`）

零构建原生 ES module + 手写 SVG 图表，无框架无 CDN（CSP 只允许 `'self'`）。
改完 scp 即生效，秒级——不必为改一句文案重发 32MB 镜像。

`ui.js` 的 `h()` 工厂**对 `html` 属性直接抛错**，所有文本走 `textContent`：
用户名、插件描述、驳回原因都是外部输入，一个 innerHTML 就是存储型 XSS。

## 三、安全模型

- **账号完全隔离**：控制台账号与 iTools 云账号是两套主体，同名也不相干。
- **令牌不明文入库**：`console_sessions` 主键是令牌的 sha256。
  主服务那边是明文主键——一次拖库即拿到全部在线会话；控制台权限更高，这里收紧了。
- **会话有 TTL 且真的会回收**：默认 8 小时 + 每 10 分钟 GC。
  （主服务的 `sessions` 永不过期、只增不减，别重蹈。）
- **鉴权靠中间件不靠自觉**：受保护路由整组套 `middleware::from_fn`。
  主服务是每个 handler 手写三行 `authenticate`，漏一个就是完全公开的端点。
- **首次登录强制改密**：守卫在 `must_change_password` 为真时拦下除改密/登出/whoami 外的一切。
  放行登出是刻意的——否则被强制改密的账号连退出都做不到。
- **角色三档**：`super` / `admin` / `viewer`，未知角色按最小权限。
  删除/降级/停用**最后一个可用超管**会被拒绝（自锁保护）。
- **登录不泄露账号是否存在**：账号不存在时也走一次口令派生，耗时接近，
  返回文案与口令错误完全相同；但审计里如实区分「账号不存在 / 口令错误 / 账号已停用」。
- **审计含失败尝试**：`ok=0` 的行同样落库。
- **SQL 注入面**：`ORDER BY` 不能参数化，故排序字段走**白名单枚举**（`UserSort`），
  未知值回落默认；`LIKE` 的搜索词做 `escape_like` 转义（`%`/`_`/`\`）。
- **敏感值不出后端**：口令哈希与盐不进任何响应；数据库地址只以 `mysql://user:***@host` 形态出现。

## 五、过程中发现并修复的问题

| # | 问题 | 修复 |
|---|---|---|
| 1 | `FLOOR()` 在 MariaDB 返回 DECIMAL，`r.get::<i64>` 直接 panic，表现为「连接被重置」这种毫无线索的故障 | 加 `CAST(... AS SIGNED)`，并把取值改成 `try_get`（类型不匹配时是可读的 500 而非 panic） |

### 关于那个独立的 frpc 实例

主 `frpc.toml` 属 `root:root`、本账号不可写，而本机的 `sudo` **只对 docker 免密**
（`synopkg restart frpc` 之类根本执行不了）。更要命的是：**SSH 端口本身就是
frp 隧道转发的**——重启 frpc 若因配置有误起不来，就再也连不上这台机器了。

因此没有动主配置，而是用 NAS 上现成的 frpc 二进制起了第二个实例（容器 `itools-frpc`，
`--restart unless-stopped`，配置 `/volume1/docker/itools-build/frpc-console.toml`，
只含 7005 一条隧道，全局段从主配置复制以复用同一个 frps token）。
现有隧道**一条都没碰**，零风险。

> ⚠ 该容器借用 `itools-console:v1` 镜像**只是为了拿一个能跑 frpc 二进制的 glibc 环境**
> （NAS 上没有独立的 debian slim 镜像，不想为此再拉一个）。清理旧镜像时别把 v1 删了，
> 或者先把这个容器重建到当前 tag。

> **建议的长期做法**：把 7005 那条 `[[proxies]]` 并进主 `frpc.toml`，再停掉 `itools-frpc` 容器。
> 需要 root，留给方便时做。在那之前这个额外容器是必需的，别误删。

> 部署时需 `export NAS_CERT_DIR=<证书目录>`（脚本里没有默认值——公开仓库不留运维拓扑）。
> 本环境该用哪个目录，看 NAS 上 `run-new5.sh` 里挂到 `/certs` 的那个卷。

### 更新方式

- 改后端 → `./deploy-to-nas.sh v2`（重新构建 + 传 32MB 镜像 + 换容器，约一分钟中断）
- 改前端 → 只需 scp `web/` 到 `$NAS_CONSOLE_WEB_DIR`，秒级、无中断

## 七、有意保留的限制项

1. **frp TCP 透传下拿不到真实客户端 IP**：服务端看到的对端恒为回环地址，
   `CONSOLE_TRUST_PROXY` 也无 XFF 可用。后果有两个，都需要知情：
   登录限流实际是**全局闸门**（一个人被限流，所有人都进不来），审计日志里的 IP 也只是回环地址。
   要真实 IP 需要 frp 改 HTTP 模式或前置反代注入 XFF。
2. **用户列表的聚合是现算的**（子查询全表扫 `data_records`）。当前几十个账号毫无压力；
   涨到十万级要改物化统计表，且应由主服务在写入时维护。
3. **首次建表在群晖上慢**（实测 1.5–3.4 秒/张，触发 sqlx 的 slow statement 警告）。
   只发生在第一次启动。
4. **控制台自身的访问量也没有采集**——它自己也没装指标中间件。第二阶段一并做。
